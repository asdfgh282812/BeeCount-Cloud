## 一、已用瀏覽器自動化驗證過的部分

操作方式：在測試帳本臨時建立「測試主帳戶群組」（`account_group`，信用額度
50000）+ 掛靠它的「測試子卡A」（`credit_card`，卡號末四碼 1234），驗證完成
後已刪除還原成原狀態。

- ✅ 舊的漸層卡片 grid（`BankCardTile`）已完全消失，改成緊湊單行列表
  （圖示 + 名稱 + 金額一行，桌面/手機寬度都是單欄，不再有 grid breakpoint）。
- ✅ 分組標題（現金/銀行/信用卡/主帳戶…）維持原本的可收合 header + 徽章
  數字 + 小計金額樣式，未受影響。
- ✅ **巢狀子帳戶**：建立掛靠 `parent_account_id` 的子卡後，子卡不再出現在
  自己 `account_type`（信用卡）的分組列表裡，改成縮排渲染在父層
  `account_group` 那一列底下，父列出現子帳戶數量徽章（例如「1」）。
- ✅ **分組標題徽章數字修正**：實測過程中發現一個問題並已修：子帳戶被巢狀
  吸收後，若分組標題徽章仍用未過濾的 `group.rows.length`，會出現「信用卡
  (2)」但只看到 1 行的落差（因為另一張已經被搬到主帳戶列底下）。已改成
  用過濾掉巢狀子帳戶後的 `topLevelCount`；某個分組的帳戶全部被吸收成子
  帳戶時（`topLevelCount === 0`），整個分組標題也會跳過不渲染，不會留一個
  空殼分組。
- ✅ 父列（有子帳戶 + 設了信用額度）名稱下方顯示「可用額度 5萬」（格式跟
  `<Amount compact>` 一致，大金額自動轉「萬/k/M」）；子帳戶名稱下方顯示卡號
  末四碼「•••• 1234」；兩者互斥不會同時出現。
- ✅ 展開/收合：父列右側的 `›` 按鈕可以獨立收合/展開自己的子帳戶清單，不
  影響外層分組本身的收合狀態。
- ✅ Hover 顯示「編輯」「刪除」文字按鈕（桌面滑鼠 hover 出現，跟舊版
  `BankCardTile` 一樣走 `group-hover:opacity-100`），子帳戶列的編輯/刪除
  按鈕也正常運作（測試中刪除了子卡跟父群組，皆彈出確認對話框、刪除成功後
  UI 正確更新）。
- ✅ 點擊列（非編輯/刪除/展開按鈕的區域）正常開啟帳戶詳情彈窗
  （`onClickAccount`），詳情彈窗內容不受影響（仍看得到 Phase 7 做的「紅利
  回饋（N 張卡）」收合按鈕）。
- ✅ 手機寬度（390px viewport）：單欄列表排版正常，縮排階層在窄螢幕下依然
  清楚可辨識，沒有橫向捲動或文字擠壓。
- ✅ 桌面寬度（1440px viewport）：列表左右不會被拉得過寬變得難以掃視（沿用
  分組卡片本身的寬度限制）。
- ✅ `pnpm -C apps/web build`（`tsc -b && vite build`）與
  `pnpm -C apps/web test:unit`（73 個測試，含 i18n 三語 key 完整性測試）
  全部通過 —— 新增的 `accounts.bankcard.availableCreditInline` key 三語
  （zh-CN/zh-TW/en）都已補齊。

## 二、需要你在正式帳本手動複測的項目

以下場景在測試帳本裡資料量不足或環境限制沒能覆蓋，請比照你原本回報問題時
的截圖情境（Image #11/#12），在瀏覽器裡實際操作：

1. **大量帳戶時的視覺/效能**：你的正式帳本有 20 張信用卡、15 個銀行帳戶，
   展開所有分組後列表會變很長，請確認：
   - 捲動流暢，沒有明顯卡頓；
   - 多層巢狀（例如「國泰世華信用卡」底下掛 3 張子卡：國泰 Cube 卡/蝦皮
     聯名卡/亞洲萬里通聯名卡）縮排看起來是否夠清楚，跟 Moze 截圖的樹狀線
     觀感是否足夠接近（目前用純縮排 + padding，沒有畫實際的樹狀連接線，
     如果你覺得不夠清楚需要加線條，請回饋，這是可以再補的細節）。
2. **多幣別帳戶**（例如截圖裡的「日幣現金」）：確認幣別金額顯示正確、
   `showCurrency` 邏輯沒有跟緊湊列表的改版打架。
3. **帳戶頭像**：有設定自訂頭像的帳戶，確認列表裡改用圓形頭像圖片正確顯示
   （取代原本卡片背景圖），沒有頭像的維持類型圖示。
4. **「可繳款」到期徽章**：有欠款且接近/超過繳款日的信用卡，確認名稱旁的
   橙色到期徽章依然正常顯示（邏輯沒有改，但渲染位置從卡片內部移到了列表
   行內，建議看一眼有沒有被裁切或跟徽章/金額擠在一起）。
5. **已隱藏帳戶分區**：`HiddenAccountsSection` 這次沒有改動（沿用原本樣式
   當作這次緊湊列表的參考基礎），確認隱藏/恢復功能沒有被波及。
6. **估值類帳戶**（不動產/車輛/投資理財/保險/公積金/貸款）：確認「當前估值
   / 當前欠款」單一數字顯示正確，貸款（負債類）的紅/綠配色符合預期。
7. **子帳戶／主帳戶各自的編輯彈窗**：從列表點「編輯」分別打開子卡跟主帳戶
   群組的編輯表單，確認掛靠關係（`parent_account_id`）、信用額度等欄位
   顯示正確，儲存後列表巢狀關係更新正確。

如果以上任何一項跟預期不符，麻煩告訴我具體是哪一項 + 截圖，我再接著修。
