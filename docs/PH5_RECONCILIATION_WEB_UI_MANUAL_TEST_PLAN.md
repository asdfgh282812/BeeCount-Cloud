## 二、需要你在浏览器里手动过一遍的清单

先确认 `make dev-api`（另开一个终端）+ `make dev-web` 都在跑（
`http://localhost:5173` 能打开），登录任意账号，选一个账本，进「帳戶」
页（或首页帳戶卡片）。

**重要**：如果这轮改动之后浏览器验证结果跟预期不符，先确认
`uvicorn --reload` 是否真的重新载入了新代码（比较进程启动时间与文件
mtime，或直接重启 `make dev-api`）再去怀疑代码逻辑本身有问题——CLAUDE.md
记过这台机器上 `--reload` 曾经安静地没捕捉到 `src/` 下的改动。

### 2.1 餘額調整

1. 点开任意非「主帳戶」（`account_type != account_group`）的帳戶卡片，
   进详情彈窗，应该能看到一个「調整餘額」（或类似措辞）的按钮/入口
2. 点开后應該顯示目前記帳餘額（唯讀）+ 一個「目標餘額」輸入框（預設帶入
   目前餘額）+ 備註欄位
3. 改「目標餘額」為比目前餘額高的數字（比如 +200），提交 → 應該成功,
   帳戶餘額卡片刷新後顯示新的餘額（可能需要關閉再打開詳情彈窗才會刷新,
   取決於前端有沒有做即時刷新——如果沒有,記錄下來當一個待改進項,不算
   阻塞性 bug)
4. 打開這筆帳戶的交易列表,應該能看到一筆新交易(類型可能顯示為「調整」
   或某個特殊標記,金額等於差額),分類欄應該是空的
5. 再次調整,這次改成比目前低的數字(負差額),確認也能成功,交易金額顯示
   為負數(或用某種方式標示「減少」)
6. 目標餘額直接填跟目前餘額一樣的數字(差額 0),確認送出仍然成功(不會
   被前端擋掉),備註能正常保存
7. 找一個「主帳戶」(account_group 類型,如果你的測試帳本裡有信用卡群組
   的話)打開詳情彈窗,確認「調整餘額」入口不會出現(或出現但點擊後顯示
   明確的錯誤訊息,不能是靜默失敗)

### 2.2 對帳模式(2026-08-09 改版,Moze 式逐筆核對清單)

準備工作:找一個(或建一個)信用卡帳戶,設定好帳單日/還款日;先記幾筆
消費交易,日期落在最近一次已結束的帳單週期內。

1. 打開這張信用卡(或它所屬的信用卡群組主帳戶)的詳情彈窗,應該能看到
   「對帳模式」區塊,標題旁邊有一個「已確認/總筆數」的小標籤(比如
   `0/3`),初始收合狀態
2. 點開展開,應該看到:①統計列(帳單筆數、新增消費金額、已確認筆數、
   已確認金額);②這期帳單的交易清單,每筆顯示分類/備註、日期、金額,
   左側有一個可點擊的圓形勾選按鈕(未確認時是空心,不是純文字「確認」
   兩個字——對應 Moze 原文的右滑手勢,網頁版改用點擊)
3. 點一筆交易左側的勾選按鈕,確認:①按鈕變成實心打勾樣式;②該筆交易
   卡片底色/邊框變化(視覺上要能一眼看出「已確認」跟「未確認」的差異);
   ③頂部「已確認筆數/金額」統計數字跟著更新;④標題旁邊的 `已確認/總筆數`
   標籤同步更新
4. 再點一次同一個勾選按鈕,確認能取消確認(狀態變回未確認,統計數字
   跟著減少)
5. 找一筆交易點「延後」按鈕,應該彈出一個對話框,預設帶入「下期帳單第一
   天」的日期(結帳日隔天),可以手動改成別的日期;提交後:①這筆交易應該
   從目前這期的清單消失,統計筆數/金額跟著減少;②切到下一期(用彈窗標題
   列的週期選擇器右箭頭切到 `cycleOffset+1`)應該能看到這筆交易出現在
   那裡,且帶有「已延後」的小標籤
6. 展開右上角的選單(⋮ 或類似圖示),應該看到至少三個選項:「新增遺漏的
   交易」(點擊應該打開一般記交易表單,日期預填在這期帳單範圍內)、
   「最新在前/最早在前」(排序切換,點擊後清單順序應該反轉)、「取消全部
   選取」(如果這期還沒有任何已確認的交易,這個選項應該是禁用/灰色狀態)
7. 先確認至少 1 筆交易,再點「取消全部選取」,應該有一個二次確認對話框
   (不能一點就清空,防手滑);確認後所有交易的確認狀態都應該歸零,統計
   數字歸零,但**延後入帳的標記不受影響**(如果上一步有延後某筆交易,
   它應該還是留在下一期,不會被這個操作拉回來)
8. 切到一個更早的歷史週期(週期選擇器左箭頭),確認裡面的交易列表跟
   確認狀態是那一期自己的,不會被上面清除確認的操作影響到(驗證「只清除
   指定週期」的邊界)
9. 找一個非信用卡帳戶(現金/銀行帳戶),打開詳情彈窗,確認「對帳模式」
   區塊**不會出現**(這個功能只對信用卡/信用卡群組有意義,對齊 Moze 原文
   入口本來就是「信用卡交易明細頁」)
10. 用一個非 owner(editor)身份登入同一個共享帳本,確認能看到並操作
    對帳模式(確認/取消確認/延後入帳/清除確認都走一般交易寫權限,不是
    owner-only,跟舊版 CRUD 不同)——這點特別容易錯,務必實測不要只看
    程式碼推論

### 2.3 延後入帳

1. 新建一筆交易(或編輯既有交易),應該能在表單裡看到一個選填的「延後
   入帳日」欄位(日期選擇器),預設空白/未設定
2. 設定一個日期後提交,確認交易明細裡能看到這個標記(可能是一行文字顯示
   延後入帳日,或一個小圖示)
3. 編輯這筆交易,清空延後入帳日,確認提交後標記消失
4. 如果測試帳本裡有信用卡帳戶,設定 billing_day,建一筆消費日在本期帳單
   窗口之外、但延後入帳日設在窗口內的交易,打開該信用卡的「信用卡帳單」
   卡片,確認 `statement_amount`/應繳金額有把這筆算進去(這一步驗證的是
   前端有沒有正確送出 `deferred_posting_at` 欄位到後端,後端邏輯本身
   pytest 已經驗證過)
5. 這個欄位也能直接從「對帳模式」清單裡每筆交易的「延後」按鈕設定(見
   2.2 第 5 步),兩個入口最終寫的是同一個欄位,行為應該一致

### 2.4 比較報表

1. 找到分析/統計相關頁面(首頁儀表板或類似位置),應該能看到一個新的
   「比較報表」卡片/區塊
2. 應該有 月/年 的切換,月模式下應該能選「跟上個月比」或「跟去年同月比」
3. 切換不同選項,確認 收入/支出/結餘 三個數字 + 漲跌百分比/箭頭正確更新
   (可以先去記帳頁面手動記幾筆本月的交易,再回來確認數字有反映)
4. 下方的分類排行列表,確認漲跌幅最大的分類排在最前面
5. 找一個完全沒有任何交易的帳本/月份切過去,確認顯示 0 而不是報錯/白屏,
   百分比欄位在「前一期是 0」時顯示合理的佔位符(比如「—」)而不是
   `Infinity%` 或 `NaN%`

### 2.5 通用檢查

1. 深色/淺色主題切換,確認上面新增的所有 UI(對帳模式已確認交易的底色/
   邊框、比較報表的漲跌箭頭顏色)在兩種主題下都清晰可辨,不會出現看不
   清楚的對比度
2. 切換語言(简中/繁中/英文),確認上面所有新增文案都有對應翻譯,不會有
   殘留的英文 key 名稱直接顯示出來(比如 `statement.title` 這種沒翻譯到
   的字串)
3. 手機瀏覽器寬度(或縮小視窗)下,對帳模式交易清單 + 比較報表卡片不會
   橫向溢出或版面錯亂
