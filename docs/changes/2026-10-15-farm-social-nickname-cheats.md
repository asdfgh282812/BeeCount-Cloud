# 農場身分、暱稱與雲端作弊器

## 原因與入口

農場社交上方原本直接列出 `GameEvent`，連「自己攤位成交」的 `market_sale`
也列入，這類紀錄的 actor 與 owner 都是自己，因此每次成交都可能多一個「自己」。
互動紀錄也一律顯示 actor，自己拜訪別人的紀錄自然還是自己的名字。
未取帳號名稱時則退回 `農夫 #帳號末四碼`，不是玩家選擇的社交身分。

- **首頁／我的 → 農場**：新建／搬遷前先取農場暱稱；既有農場未取名者，
  下次連線進入農場時提示補填。取消新建的取名步驟不會建立農場。
- **農場 → 設定 → 農場暱稱**，或 **農場 → 社交 → 右上角名牌圖示**：修改暱稱。
  名稱去除頭尾空白，限 1～20 個 Unicode 字元，不含控制字元；Cloud 為權威。
- **農場 → 社交**：最近互動與農友清單分開；互動顯示對方暱稱與「你 → 對方／
  對方 → 你」方向。攤位成交不再混入。農友列表另防守排除自己及重複 userId。
- **農場 → 設定 → 農場作弊器**：恢復 debug 建置的工具。單機沿用既有工具；
  雲端需伺服器管理員，所有指令操作目前帳號農場，收到權威 snapshot 後刷新。
  這次沒有把 debug 工具開放至 release/profile 或一般雲端帳號。

## 實作與取捨

Cloud 將農場專用 `nickname` 存於既有 `GameFarm.state` JSON，無 DB migration，
不修改個人資料的名稱，也不把本機遊戲亂數 seed 當登入身分。舊客戶端仍可呼叫
既有建立 API；新 App 建立流程要求填名。未補填的舊玩家顯示「尚未取暱稱的農友」，
不顯示帳號編號。匿名排行榜沿用既有匿名規則。暱稱不要求唯一，操作仍以 userId 識別。

Cloud 事件回應新增 `counterpartyId`／`outgoing`，`displayName` 改為互動對方。
伺服器與 App 皆排除自己對自己的事件，涵蓋尚未更新的伺服器與既有成交資料。

雲端作弊器走獨立 `/game/debug/actions`，伺服器檢查 App scope 與管理員資格；
沿用交易與 requestId receipt，重送不重複加幣，錢包 reason 為 `debug_cheat`。
`CloudFarmCheats` 將原有完整工具映射至此 API，不修改本機 DB。
測試天氣只作用於自己，不改共用城市天氣；重新整理真實天氣會清除覆寫。
雲端重置直接回到新的初始農場並保留暱稱；單機重置維持清除存檔的舊行為。
這些是管理員測試指令，會直接改真實農場進度，沒有另建沙盒或排行榜資料修復機制。

Web 依既有範圍仍只有排行榜，同步顯示農場暱稱與未命名備援，頁面提示 App 的取名入口；
不新增農場場景、社交操作或 Web 作弊器。兩端維持 `feat/v4-dev`，沒有合併或部署；
上線仍需 Cloud → Web → App。

更新既有 `farm.cloud.v4`（暱稱、作弊器）與 `farm.social.v4`（暱稱、互動）導覽，
id 不更名；3.8.3 雲端農場 What's New 也補上暱稱說明。
