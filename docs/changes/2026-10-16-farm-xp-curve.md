# 農場 XP 曲線與 App 對齊

使用者確認：升到 2 級需要 50 XP，後續每次升級需求增加 50%，每級捨去小數並以該整數再計算下一級。需求依序 50、75、112、168、252、378……；升到 2～5 級的累積門檻是 50、125、237、405。

`balance_v1.json` 將 `xpPerLevel` 設為 50 並新增 `xpGrowthPercent=50`。`rules.xp_progress`／`xp_for_level`／`level` 統一處理整數進度與累積門檻；`engine.py` 的購買、播種、擴田全部走共用等級公式，社交原本就使用 `rules.level`。除錯升級按累積門檻設定 XP，超過 JSON 安全整數的級數夾到可保存上限（目前 80 級）。缺少新比例欄位的舊設定維持固定需求。

既有總 XP 保留，等級按新公式重算，不新增 migration，也不回收既有田地／庫存。高 XP 舊玩家可能顯示較低等級；之後的解鎖與擴田依新等級判定。每次收成仍給 10 XP，超額經驗會保留。

App 入口：首頁／我的 → 農場 → 上方等級膠囊，顯示本級已得 XP／需求；導覽 `farm.guide.home.v4` 與 3.8.3 公告同步更新。Web 只有排行榜，沒有種植／等級 UI，不新增遊戲畫面。兩端仍在 `feat/v4-dev`，本次沒有部署。

測試包含雙端手算累積門檻與各級前後邊界、舊設定、高級數及除錯工具。API 檢查 236 XP 拒絕購買／播種葡萄且不扣資源，237 XP 正常解鎖。12 週三種玩家與固定田數的經濟模擬結果和原 golden 一致，所以只更新設定 SHA，不更動行情、收成或經濟 golden。

實際結果：完整 Cloud game 156 項、App 農場／導覽 325 項通過；比例為 JSON `50.0` 的相容性另跑兩端 progression 各 3 項通過。Ruff、Dart analyze、跨 repo 契約與兩端 diff 檢查通過。
