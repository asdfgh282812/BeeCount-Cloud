## 二、如果你想自己在浏览器里再复核一遍，可以对照这份清单

（跟上面「一之 3」的步骤基本相同，这里拆成更细的检查点方便你逐条打勾）

先 `make dev-api`（另开一个终端）+ `make dev-web`，登录任意账号，找一个
已有「餐饮」「交通」等支出分类、至少一个收入分类（没有就先在「分类」
页建几个）的账本。

### 2.1 拆帳交易的「退款」按钮不再灰掉

1. 建一笔支出 200，开「拆分到多个分类」，填「餐饮 150」+「交通 50」，
   提交
2. 打开这笔交易详情 —— 「拆分」徽章 + 分类明细两行都在
3. 看右下角「退款」按钮：**应该是正常可点击状态**（不是灰色），鼠标
   悬停不应该再出现「拆帳交易不能整笔退款」之类的提示

**预期**：按钮可点击，跟一笔普通（非拆帳）支出交易的退款按钮观感一致

### 2.2 退款表单预填 + 分类留空

1. 点「退款」—— 应该关闭详情弹窗、打开「新建交易」表单
2. 检查预填：类型=收入（因为原交易是支出）、金额=200（原交易金额）、
   备注/账户跟原交易一致、**分类栏是空的**（需要你自己选一个收入分类）
3. 分类栏旁边**不应该**出现「拆分到多个分类」开关的既定勾选状态（开关
   本身可能还在，但不应该默认开启 —— 这是新建交易表单的通用行为，不是
   退款专属）

**预期**：跟对一笔非拆帳交易点「退款」的预填表现完全一样

### 2.3 部分退款成功 + 双向勾稽

1. 把金额改小一点（比如 80，测试部分退款），选一个收入分类，提交
2. 提交应该成功，交易列表出现这笔新的退款交易
3. 回去打开原交易（拆帳那笔）详情：
   - 分类明细（餐饮 150 / 交通 50）应该完全不变
   - 应该新增一行「已退款金額 80.00」，下面列出这笔退款交易，可以点击
   - 「退款」按钮现在应该变灰，鼠标悬停提示「这笔交易已经退过款」
4. 点已退款清单里的那一条，应该跳转到那笔退款交易的详情，显示「退款」
   徽章，点徽章能跳回原交易

**预期**：整套双向勾稽 + 禁止重复退款的行为，跟非拆帳交易退款完全一致

### 2.4 统计页联动

1. 回首页 / 统计页，确认本月支出净额 = 拆帳交易金额 − 退款金额
   （用上面例子是 200 − 80 = 120）
2. 分类排行里「餐饮」「交通」两项金额应该维持 150/50 不受退款影响
   （退款净额只冲抵全局支出，不会按比例拆回这两个分类各自扣减）

### 2.5 退款交易本身依然不能拆帳（回归检查，确认没被这次改动破坏）

1. 对任意一笔交易（拆帳或非拆帳都行）点「退款」，打开退款表单
2. 尝试打开「拆分到多个分类」开关，填好两行分类+金额（加总等于退款
   金额）
3. 点提交 —— **应该被挡下**，弹出错误「退款交易不支援拆分到多個分類」
   （或对应语言的翻译），不能成功创建

**预期**：这条互斥不受影响，仍然生效

## 三、已知限制（跟改动前一致，未变更）

- **拆帳子项目个别退款**：Moze 原文支持对拆帳交易的某个子分类单独退款
  （比如只退「交通」那 50 元），BeeCount 目前仍然只支持整笔退款——
  这次改动只是把「拆帳交易不能整笔退款」的挡拿掉，没有实现子项目级别
  的退款颗粒度。需要部分退某个分类时，用户可以手动把退款金额改小
  （部分退款机制本身是支持的），但退款金额不会跟某个具体 split 明细
  绑定。
- **CSV 导出** / **mobile 端子表**：跟 Phase 2/Phase 1.5 落地时的已知
  限制一致，未变更，详见 `docs/PH2_SPLIT_WEB_UI_MANUAL_TEST_PLAN.md`
  第三节。
